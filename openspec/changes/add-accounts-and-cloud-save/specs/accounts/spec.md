# Spec Delta

## Purpose
Letting a player keep a game account without passwords or personal data, using passkeys, with safe recovery and full deletion.

## ADDED Requirements

### Requirement: Passkey-only sign-up
The system SHALL create accounts only through a passkey ceremony that requires user verification (biometric or device PIN), and MUST NOT accept passwords, email addresses or real names.

#### Scenario: Creating an account
- **WHEN** a player chooses "Save my progress" and completes the passkey prompt
- **THEN** an account is created with a generated display name, the player is signed in, and ten recovery codes are shown once

#### Scenario: Passkey prompt cancelled
- **WHEN** the player cancels the passkey prompt
- **THEN** no account is created and the game keeps working as a guest

### Requirement: Passkey sign-in without a username
The system SHALL let a returning player sign in by choosing a saved passkey, without typing a username.

#### Scenario: Signing in on a new device
- **WHEN** a player signs in with a passkey synced to their new device
- **THEN** they are signed in and their cloud progress is loaded

#### Scenario: Replayed or forged assertion
- **WHEN** a sign-in response reuses an old challenge, comes from another origin, lacks user verification, or fails signature checks
- **THEN** sign-in is refused with a generic error that does not say which check failed

### Requirement: Sessions
A signed-in session SHALL be identified only by a random token in a cookie that scripts cannot read and other sites cannot send, SHALL expire after 7 days of inactivity and 30 days in total, and the server SHALL store only a hash of the token.

#### Scenario: Idle session
- **WHEN** a session is unused for more than 7 days
- **THEN** the next request is treated as signed out

#### Scenario: Stolen database copy
- **WHEN** an attacker obtains a copy of the session table
- **THEN** they cannot use it to sign in, because only token hashes are stored

### Requirement: Sign-out
Players SHALL be able to sign out on this device or on all devices.

#### Scenario: Sign out everywhere
- **WHEN** a player chooses "Sign out on all devices"
- **THEN** every session of that account stops working immediately

### Requirement: Recovery codes
At sign-up the system SHALL issue ten single-use recovery codes of at least 80 bits of randomness each, show them once, and store only their hashes. Using a code SHALL sign the player in and invalidate that code.

#### Scenario: All passkeys lost
- **WHEN** a player enters an unused recovery code
- **THEN** they are signed in and asked to add a new passkey

#### Scenario: Reused code
- **WHEN** a player enters a code that was already used
- **THEN** sign-in is refused

### Requirement: Account deletion
Players SHALL be able to delete their account, which SHALL permanently remove the account, its passkeys, sessions, recovery codes and cloud progress.

#### Scenario: Deleting an account
- **WHEN** a signed-in player confirms "Delete my account"
- **THEN** all server data for that account is removed, they are signed out, and local progress on the device is kept

### Requirement: Generated display names
Display names SHALL be generated by the server from a fixed word list plus digits, so that players never type free text that could contain personal data.

#### Scenario: New account name
- **WHEN** an account is created
- **THEN** it receives a name such as "Golden Diya 4821"
